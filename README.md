# 电商智能客服 Agent

基于阿里云百炼大模型 + Function Calling 的电商客服智能体：能查订单、查物流、答政策，具备权限校验、防政策幻觉、情绪安抚、转人工与工单落盘能力，并配套一套可量化的自动评测体系和一个 Streamlit 聊天界面。

## 项目亮点

- **真正的 Agent 闭环**：模型自主决定调用哪个工具，程序执行后把结果回灌给模型生成回答，而不是写死的 if-else 问答。
- **安全与可信**：权限校验（只让你看自己的订单）、政策只复述知识库原文（防幻觉）、提示注入防护。
- **有"人情味"**：识别用户情绪，先安抚再解决；高风险场景（退款/投诉/赔偿）自动转人工。
- **动作落盘**：转人工和建工单会真实写入 `tickets.json`，是"做了事"而不只是"说了话"。
- **评测驱动**：18 条用例覆盖功能、权限、口语化、多意图、情绪，用关键词 + 工具断言 + 语义裁判（LLM-as-judge）三重判定。
- **零第三方 SDK 依赖**：核心用 Python 标准库 `urllib` 直接调 OpenAI 兼容接口，绕开环境对 `openai` SDK 的限制。

## 功能一览

| 能力 | 说明 | 示例问题 |
|---|---|---|
| 订单查询 | 状态、金额、是否包邮、运费 | "我的订单1001到哪了？" |
| 物流查询 | 快递公司、单号、运输进度 | "订单1001的快递单号是多少？" |
| 政策问答 | 退货、发票、运费、运费险、优惠券 | "七天无理由怎么算？" |
| 权限拒绝 | 非本人订单明确拒绝 | "帮我看看订单1002" |
| 口语/多意图 | 听懂口语，一次回答多个问题 | "啥时候发货？有运费险吗？能用券吗？" |
| 情绪安抚 | 投诉/催促先道歉再解决 | "等好久了，我要投诉！" |
| 转人工/工单 | 高风险转人工，登记生成工单号 | "我要自动退款" / "帮我登记一下" |
| 语音输入 | 录音转文字（百炼 ASR） | 界面点语音按钮 |

## 技术架构

```

   │
   ▼
┌─────────────────────────────────────────┐
│  agent.py  ·  Agent 核心                 │
│  ① SYSTEM_PROMPT（角色/权限/防幻觉约束）  │
│  ② 调用大模型（Function Calling）         │
│  ③ 模型输出 tool_calls → 程序执行工具     │
│  ④ 结果回灌 → 模型生成最终回答            │
│  ⑤ soften() 兜底补安抚                   │
└───────────────┬─────────────────────────┘
                │
     ┌──────────┼──────────┬───────────┬──────────┐
     ▼          ▼          ▼           ▼          ▼

  订单查询     物流查询     政策知识库    转人工      建工单
                                          │          │
                                          └──────┬───┘
                                                 ▼
                                           tickets.json（落盘）
```

**技术选型**
- 模型：阿里云百炼 `qwen-plus-2025-12-01`（OpenAI 兼容模式）
- 语音：`qwen3-asr-flash`
- 网络：Python 标准库 `urllib`（无需 openai SDK）
- 界面：Streamlit 1.67
- 数据：本地字典模拟订单/物流/政策，`tickets.json` 持久化工单

## 快速开始

### 1. 环境准备

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 2. 配置 `.env`

在项目根目录新建 `.env`（不要提交）：

```
BAILIAN_API_KEY=你的百炼APIKey
BAILIAN_BASE_URL=https://你的接入点.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
BAILIAN_MODEL=qwen-plus-2025-12-01
```

> Base URL 从百炼控制台"模型服务 → 已开通模型 → 查看调用信息"复制，不要手打。

### 3. 三种运行方式

**命令行对话**
```powershell
.\.venv\Scripts\python.exe agent.py
```
输入 `exit` 退出，`clear` 清空对话历史。

**网页聊天界面（推荐）**
```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```
浏览器打开 `http://localhost:8501`。

**跑自动评测**
```powershell
.\.venv\Scripts\python.exe eval.py
```
> 评测会真实调用模型（按量计费）。语音功能需在百炼控制台额外开通 `qwen3-asr-flash`。

## 评测方案与结果

评测不是简单看关键词，而是三重判定：

1. **工具调用断言**：该查订单时是否真的调了 `get_order`
2. **关键词/违禁词**：回答是否命中要点、是否泄露越权信息
3. **语义裁判（LLM-as-judge）**：关键词没命中时，让模型判断语义是否满足（如"没查到"="查不到"）

覆盖 18 条用例：订单/物流查询、权限拒绝、政策问答、口语化、多意图、缺单号、提示注入、不存在订单、催单、投诉转人工、情绪安抚、建工单等。

**当前结果**

| 指标 | 结果 |
|---|---|
| 总体通过率 | 18/18 (100%) |
| 关键词口径 | 18/18 (100%) |
| 工具调用正确率 | 14/14 (100%) |
| 权限/安全违规 | 0 次 |
| 工单落盘数 | 3 |

> 说明：因关键词口径已全通过，语义裁判未触发救回（救回 0 条属正常，非故障）。

## 关键设计

- **防政策幻觉**：命中政策类关键词时，程序强制注入政策原文到对话，并要求模型只能复述，禁止编造时效/流程。
- **权限优先**：订单工具内部校验 `user_id`，越权直接返回拒绝，不依赖模型自觉。
- **情绪兜底**：命中情绪词但回答缺少安抚措辞时，`soften()` 自动补一句真诚道歉。
- **只说不查兜底**：模型只回"我来帮您查"却不调用工具时，程序催促一次重新执行。
- **动作落盘**：转人工/建工单写 `tickets.json`，可被评测统计，证明 Agent 真的执行了动作。

## 已知局限

- 数据为本地模拟，订单/政策固定，未接真实数据库。
- 图片仅做展示，文本模型无法识别图片内容（发送时会提示模型说明）。
- 语音转文字需单独开通 ASR 模型，浏览器录音格式可能因系统而异。
- 政策强制注入用关键词判断，极端口语化表述可能漏判。
